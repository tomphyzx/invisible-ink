# Before making the repository public

The repository starts private at `tomphyzx/invisible-ink`. Work through this list, then switch it
to public. Once public, forks and clones cannot be recalled, so everything below is checked first.

## 1. Nothing private in the files or the history

The repository was started fresh, not copied from Submission Cleaner, so no course, roster or
student data is in its history. Confirm it:

```bash
git log --all --format='%an <%ae>' | sort -u          # only the intended author names
git grep -n -i -E 'PHY ?152|brightspace|roster|tom-dunbar|/home/|dropbox' $(git rev-list --all) | head
git grep -n -E '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}' $(git rev-list --all) | head
```

Expected: no hits apart from the `example` address style in tests, if any.

- [ ] Every test file is generated by `tests/make_samples.py`; no real document is committed.
- [ ] No screenshots or sample outputs made from real documents.

## 2. It works on a clean machine

- [ ] CI (`.github/workflows/tests.yml`) is green on GitHub.
- [ ] `bin/invisible-ink check` and a scan run on a Mac (no sandbox; the warning shows).
- [ ] Scanned a handful of real documents of each kind (PDF exports from Word and Google Docs,
      a scanned PDF, a `.docx`, a phone photo) with no false alarms.

## 3. The page people land on

- [ ] README example output matches what the current version prints.
- [ ] Repository description: "Find and remove text a reader can't see but an AI will read."
- [ ] Topics: `prompt-injection`, `hidden-text`, `pdf`, `docx`, `llm-security`, `ai-safety`.
- [ ] `SECURITY.md` or a line in the README on how to report a bypass privately (an email
      address, or GitHub private vulnerability reporting switched on).

## 4. Release

```bash
git tag -a v0.1.0 -m "Invisible Ink 0.1.0"
git push origin main --tags
gh repo edit tomphyzx/invisible-ink --visibility public --accept-visibility-change-consequences
gh release create v0.1.0 --title "Invisible Ink 0.1.0" --notes-file docs/release-notes-0.1.0.md
```
